# דוד חכם 🔥☀️

אפליקציה (PWA) שמחשבת **מתי ולכמה זמן להדליק את הדוד** בחורף, לפי:
- **תחזית מזג האוויר** (Open-Meteo, חינם, בלי מפתח): קרינת שמש לפי שעה, עננות וטמפרטורה.
- **הקולטים הסולאריים**: כמה השמש כבר חיממה עד שעת המקלחות.
- **בני הבית**: מי מתקלח, כמה דקות, בוקר או ערב, אמבטיות לילדים.
- **הדוד**: נפח, הספק גוף החימום, טמפ׳ מקסימלית.

ושולטת במתג **Switcher** דרך "סוכן בית" קטן.

## איך החישוב עובד
1. **מים קרים ברשת** ≈ ממוצע טמפ׳ האוויר בשבוע האחרון + 2° (בין 12° ל-26°).
2. **ביקוש**: ליטרים ב-40° (ספיקה × דקות, או נפח אמבטיה) ← אנרגיה בקוט״ש.
3. **טמפ׳ יעד בדוד**: מה שנדרש כדי שהדוד יכיל את האנרגיה הזו (85% ניצולת, מינימום 45°, עד התרמוסטט).
   אם הדוד קטן מדי לכולם ברצף – מופיעה אזהרה.
4. **שמש**: קרינה לפי שעה × שטח קולטים × נצילות, מהזריחה עד שעת המקלחת (רק בערב).
5. **חימום חשמלי** = מה שחסר + הפסדי המתנה, מעוגל ל-5 דקות. החימום מסתיים 10 דק׳ לפני המקלחת
   (או לפני שעות השיא, אם הפעלתם "תעו״ז").
6. **כיול**: אחרי מקלחת לוחצים 🥶 / 👌 / 🔥 – המקדם מתעדכן (‎±10–15%) והחישוב מתאים את עצמו לבית שלכם.

הקוד: [`js/model.js`](js/model.js) (משותף לאפליקציה ולסוכן), בדיקות: [`tests/model.test.js`](tests/model.test.js).

## שליטה ב-Switcher – שתי דרכים
| | 📱 אפליקציית אנדרואיד (בלי מחשב) | 🏠 סוכן בית (מחשב/Raspberry Pi) |
|---|---|---|
| מה צריך | רק את הטלפון | מחשב שדלוק תמיד בבית |
| איך הדוד נדלק | הטלפון כותב לתוך המתג **תזמונים חד-פעמיים**, והמתג מפעיל אותם בעצמו | הסוכן מדליק את המתג בזמן הנכון |
| מתי מתעדכן לפי מזג האוויר | בכל פעם שהטלפון ב-Wi-Fi של הבית (בערך פעם בשעה) | כל דקה |
| כיול אוטומטי | הספק גוף החימום, כשהסנכרון תופס חימום | הספק + ניתוקי תרמוסטט |

## 📱 אפליקציית אנדרואיד
אותו ממשק כמו אפליקציית הווב, ובנוסף:
- **🔍 חיפוש המתג ברשת** (⚙️ הגדרות): המתג משדר את פרטיו ב-Wi-Fi, והאפליקציה מוצאת אותו לבד (IP, מזהה, מפתח).
- **סנכרון**: בפתיחת האפליקציה, ובערך פעם בשעה ברקע כשהטלפון ב-Wi-Fi, האפליקציה מחשבת את התוכנית
  וכותבת למתג את חלונות החימום של **24 השעות הקרובות** כתזמונים חד-פעמיים. המתג מפעיל אותם גם כשאתם לא בבית.
  אם התחזית השתנתה – רק התזמון שהשתנה מוחלף.
- **התזמונים שלכם באפליקציית Switcher לא נמחקים**: האפליקציה מוחקת רק תזמונים שהיא עצמה יצרה
  (לפי מזהה + שעת התחלה + שעת סיום + חד-פעמי). במתג יש 8 מקומות לתזמונים; אם הם מלאים מוצגת אזהרה.

### התקנה
1. ב-GitHub: **Releases → `boiler-latest` → `boiler.apk`** – להוריד בטלפון ולפתוח (לאשר "התקנה ממקור לא ידוע").
2. לפתוח את "דוד חכם" כשהטלפון ב-Wi-Fi של הבית → ⚙️ הגדרות → **🔍 חיפוש המתג ברשת**.
3. למלא בני בית, דוד ומיקום. במסך "היום" מופיע כרטיס "📱 המתג מתוכנת מהטלפון" עם התזמונים שנכתבו.

> חתימה קבועה (כדי לעדכן גרסה בלי למחוק): כמו ב-kids-reminders, עם הסודות `BOILER_KEYSTORE_BASE64`,
> `BOILER_KEYSTORE_PASSWORD`, `BOILER_KEY_ALIAS`, `BOILER_KEY_PASSWORD`.

### איך זה בנוי ונבדק (`android/`)
- `core/` (Kotlin, נבדק בלי אנדרואיד: `gradle -PcoreOnly=true :core:test`):
  - `Switcher.kt` – הפרוטוקול המקומי של מתגי Switcher לדוד (V2/V4/Touch/Mini), מועתק מספריית הקוד הפתוח aioswitcher.
    הבדיקות משוות **בייט-בייט** לחבילות ש-aioswitcher עצמה מייצרת (`tools/switcher_vectors.py`).
  - `Planner.kt` – העתק של חישוב התוכנית מ-`js/model.js`. הבדיקות משוות לתוצאות של `model.js` עצמו
    (`tools/planner_vectors.mjs`), וה-CI נכשל אם `model.js` השתנה בלי לעדכן את ה-Kotlin.
  - `ScheduleSync.kt` – מה למחוק/ליצור במתג; נבדק מקצה לקצה מול מתג מדומה שבודק חתימה של כל חבילה.
- `app/` – WebView שמציג את אותו ממשק (`index.html`, `js/`, `css/` נארזים לתוך ה-APK), גשר לקוד הנייטיב,
  חיפוש המתג, ועבודת רקע (WorkManager) לסנכרון.

## 🏠 סוכן הבית (אופציונלי)
אם יש בבית מחשב שתמיד דלוק (Raspberry Pi, NAS, מחשב ישן), אפשר במקום האפליקציה להריץ עליו סוכן – הוא מתעדכן כל דקה
ולומד גם מניתוקי התרמוסטט:

- [`switcher_webapi`](https://github.com/TomerFi/switcher_webapi) (קוד פתוח) – מדבר עם המתג.
- [`agent/agent.mjs`](agent/agent.mjs):
  - כל דקה מחשב את התוכנית ובזמן ההתחלה שולח `turn_on` **עם טיימר כיבוי אוטומטי** – גם אם הסוכן נופל, הדוד לא נשאר דלוק.
  - **מודד את צריכת החשמל מהמתג** בזמן החימום ולומד ממנה (ראו למטה).
  - **מגיש את האפליקציה ברשת הביתית** בכתובת `http://<כתובת-המחשב>:8080` – משם רואים מצב חי (דולק/כבוי, וואטים),
    הגדרות נשמרות ישירות בסוכן, וכפתורי "הדלק עכשיו" / "כבה" עובדים.

### כיול אוטומטי ממדידות המתג
ה-Switcher מדווח את ההספק הרגעי. הסוכן קורא אותו כל דקה בזמן חימום ומחשב את האנרגיה שנכנסה בפועל:
1. **הספק גוף החימום האמיתי** (למשל 2.3 קו״ט ולא 2.5 שעל המדבקה) – מחליף את ההנחה בחישוב משך החימום.
2. **ניתוק תרמוסטט** – אם המתג דלוק וההספק יורד ל-0 (שתי קריאות ברצף), המים הגיעו לטמפ׳ המקסימלית.
   מכאן יודעים כמה חמים היו המים *לפני* החימום (מקס׳ פחות האנרגיה שנכנסה), ומשווים למה שהמודל הניח (מים קרים + שמש).
   אם המים היו חמים יותר – המקדם יורד, והחימום הבא קצר יותר.
3. **ריצה ארוכה בלי ניתוק** – אם נכנסה כל כך הרבה אנרגיה שהמים *לא יכלו* להתחיל חמים כמו שהמודל הניח – המקדם עולה.

כל ריצה מזיזה את המקדם 30% לכיוון הערך שנמדד (כדי שיום חריג לא ישבש), בגבולות ‎×0.5–×1.6.
המקדם האוטומטי מוכפל במקדם של המשוב הידני (🥶/👌/🔥). ריצות ידניות ("הדלק עכשיו") לא משמשות ללמידה.
הכל נראה בכרטיס "🏠 סוכן הבית" במסך "היום", ואפשר לאפס ב-⚙️ → כיול.

> כדי שהניתוק יזוהה, טמפ׳ ה"מקסימלית" בהגדרות צריכה להתאים לתרמוסטט של הדוד (בדרך כלל 60°–70°).

### התקנה
1. במחשב הביתי, בתיקייה `boiler/agent/`:
   ```bash
   docker compose up -d
   docker compose logs -f agent
   ```
   בלי Docker: מריצים את switcher_webapi לפי ההוראות שלו, ואז `SWITCHER_API=http://localhost:8000 node agent.mjs` (Node 18+).
2. בטלפון פותחים `http://<כתובת-המחשב>:8080` ← ⚙️ הגדרות → "שליטה ב-Switcher": סוג המתג (`v4`/`touch`/`v2esp`/`v2qual`),
   כתובת IP ומזהה המכשיר (מופיעים באפליקציית Switcher או בלוג של switcher_webapi). ממלאים גם את בני הבית והדוד.
3. הרצה ראשונה בלי להדליק באמת: `DRY_RUN=1` (שורה מוכנה ב-`docker-compose.yml`). התוכנית: `node agent.mjs --plan`.

ההגדרות והלמידה נשמרות ב-`agent/data/`. ה-API פתוח לכל מי שמחובר לרשת הביתית (בלי סיסמה) – אל תחשפו את פורט 8080 לאינטרנט.
גרסת GitHub Pages ממשיכה לעבוד כמתכננת בלבד (בלי מצב חי), ואפשר להוריד ממנה קובץ הגדרות ל-`agent/data/boiler-config.json`.

## מגבלות ידועות
- המודל לא יודע את הטמפ׳ האמיתית במים – הוא מניח שהדוד "התרוקן" אחרי המקלחות הקודמות. הכיול מפצה על זה.
- מקלחות בוקר לא מקבלות קרדיט על שמש של אתמול.
- חימום שאמור להתחיל לפני חצות (למשל מקלחת ב-01:00) לא מופעל ע״י הסוכן.
- המודל לא מקבל טמפ׳ אמיתית – הלמידה נשענת על ניתוקי התרמוסטט. אם המים אף פעם לא מגיעים למקסימום, הכיול יעלה רק כשברור שחסר.
- לא נבדק עדיין מול מתג אמיתי – רק מול שרת מדומה (כולל סימולציה של ניתוק תרמוסטט). ההרצה הראשונה כדאי שתהיה עם `DRY_RUN=1`.
- **אפליקציית האנדרואיד לא נבדקה מול מתג אמיתי.** הפרוטוקול זהה בייט-בייט ל-aioswitcher (שעובדת עם מתגים אמיתיים, למשל ב-Home Assistant), אבל ההתנהגות של תזמון חד-פעמי שנכתב היום לשעה של מחר מבוססת על ההנחה שהמתג מפעיל אותו במופע הבא של השעה. כדאי לבדוק בפעם הראשונה באפליקציית Switcher שהתזמונים מופיעים.
- לא ידוע אם switcher_webapi מחזיר את `power_consumption` בכל דגמי המתג – אם הכרטיס מציג "עוד לא נמדד" אחרי חימום, זה הסימן.
